# Overview

Cloudflare's Rust implementation of IETF MoQ Transport. Provides both relay and client functionality, strictly following the IETF MoQ working group specifications. One of the most active implementations in the ecosystem.

# History

**Timeline**:
- **2022-06-29**: Luke Curley creates `kixelated/warp` (Go implementation)
- **2023-04–05**: Luke rewrites from Go to Rust (PR #15, May 22)
- **Mid-2023**: Mike English begins collaborating closely with Luke — near-daily discussions on codebase design and the evolving IETF MoQ Transport spec. Mike's contributions include early containerized relay deployments (Fly.io, GKE), the first MoQT client publisher (moq-pub), an exploration of C FFI for ffmpeg ([englishm/libmoq](https://github.com/englishm/libmoq)), and an update to support draft-ietf-moq-transport-04. See Mike's [pre-fork commits](https://github.com/moq-dev/moq/commits?author=englishm).
- **2024-10-07**: Luke publishes his ["Fork" blog post](https://moq.dev/blog/transfork), stepping away from the IETF WG to focus on moq-lite/Transfork
- **2024-10-15**: Mike creates `englishm/moq-rs` (fork of Luke's repo) to maintain IETF WG alignment
- **Later**: Transferred to Cloudflare as `cloudflare/moq-rs`

The two projects are now considered **sibling implementations** — neither is upstream of the other. See [[moq-dev]] for Luke's original project.

# Recent Highlights (as of October 2026)

Day-by-day PR/issue history lives in [[log|the wiki log]]; this section keeps only durable milestones.

- **draft-18 landed and a registered relay went live.** [PR #173](https://github.com/cloudflare/moq-rs/pull/173) ("Start work on draft-18", englishm) opened on the London hackathon floor June 9 and merged June 11. A rolling `draft-18-dev` branch ([PR #176](https://github.com/cloudflare/moq-rs/pull/176)) auto-deploys to `draft-18-interop.cloudflare.mediaoverquic.com:443` and is registered in the [[interop-runner]] as `moq-rs-draft-18` — closing a long-standing two-draft gap (`main` stays draft-14). The follow-on [PR #178](https://github.com/cloudflare/moq-rs/pull/178) removes `MAX_REQUEST_ID` and moves requests onto bidi streams (cf. [[moq-transport]] [Issue #1653](https://github.com/moq-wg/moq-transport/issues/1653)); it merged in a July-8 burst that also shipped `moq-relay-ietf` v0.7.21.
- **CAT bearer-token authorization landed (2026-10-06).** The AuthHook / CAT-for-MoQ work that had sat OPEN as a coordination venue since the summer ([PR #169](https://github.com/cloudflare/moq-rs/pull/169) proposing an AuthHook trait for intra-scope relay authorization; [PR #171](https://github.com/cloudflare/moq-rs/pull/171), [[suhas-nandakumar|Suhas]], the `moq-auth` / `moq-auth-cat` crates; [[thibault-meunier|Thibault Meunier]]'s review pushing toward issuer-aware challenge/reply so it also fits [[moq-privacy-pass|PrivacyPass]]) **merged to `main` as [PR #235](https://github.com/cloudflare/moq-rs/pull/235) *"feat(auth): CAT bearer-token authorization"* (+8,933/−1,120)** — gated behind a **default-off `auth-cat` feature** — and shipped in the v0.7.28 train. This is moq-rs's first shipped relay-authorization mechanism (CAT = Common Access Token).
- **draft-18 CAT authorization rework begins (2026-10-12) — shipped in v0.7.29.** After the v0.7.28 draft-16 CAT work, [[mike-english]] started reworking relay authorization for **draft-18 CAT**. Phase **C1** — [PR #257](https://github.com/cloudflare/moq-rs/pull/257) *"C1 auth foundations for draft-18 CAT"* (+3,549/−12) — lays a fresh `moq-relay-ietf/src/auth/` scaffold: an `AuthzOperation` type with six variants matching the CAT `MoqtAction` claim (`Subscribe`, `SubscribeNamespace`, `Fetch{namespace,track}`, `Publish`, `PublishNamespace`, `TrackStatus`), an async `AuthHook` trait (`on_setup`/`on_request`) with allow-all/deny-all defaults, scope config (keys/issuers/audience), and **AUTHORIZATION TOKEN parameter wire parsing in SETUP**; actual policy enforcement (`CatAuthHook`) and relay-gate wiring are deferred to a later phase (C2). The companion [PR #258](https://github.com/cloudflare/moq-rs/pull/258) *"FETCH requires Fetch(7) CAT action"* (+310/−50) **corrects the action mapping** so FETCH authorizes against the CAT `Fetch(7)` action (draft-16 §9.16) instead of the old `Subscribe(4)` — a token granting only `Subscribe(4)` can no longer FETCH. Both shipped in the **v0.7.29** train (Oct-12). A follow-on [PR #259](https://github.com/cloudflare/moq-rs/pull/259) *"add DraftVersion enum for multi-version ALPN negotiation"* (a `DraftVersion{Draft18,Draft20,Draft22}` runtime type so one binary can negotiate -18/-20/-22) is **open/unmerged** — the foundation for concurrent multi-version support. **The next phase shipped two days later in v0.7.30 (Oct-14):** scope-policy loading from a `--scope-config` file ([PR #269](https://github.com/cloudflare/moq-rs/pull/269)/[#271](https://github.com/cloudflare/moq-rs/pull/271)) and AUTHORIZATION-TOKEN presentation in SETUP ([PR #270](https://github.com/cloudflare/moq-rs/pull/270)) move the auth work from scaffold toward enforcement, with [PR #267](https://github.com/cloudflare/moq-rs/pull/267)/[#268](https://github.com/cloudflare/moq-rs/pull/268) admitting internal relay peers on token-policy scopes and [PR #266](https://github.com/cloudflare/moq-rs/pull/266) (nnazo) falling back to the cached scope policy when the coordinator is unreachable.
- **The relay now serves FETCH on draft-18 (2026-10-14) — shipped in v0.7.30.** A three-PR batch ([[mike-english]]) brought **FETCH serving to the draft-18 relay role**, well beyond the Oct-6 draft-14/`main` passthrough-and-client-fetch stack: [PR #272](https://github.com/cloudflare/moq-rs/pull/272) *"make FETCH session plumbing functional on draft-18"* (+919/−43), [PR #273](https://github.com/cloudflare/moq-rs/pull/273) *"serve standalone FETCH on draft-18 (transport + relay passthrough)"* (+4,974/−80), and [PR #274](https://github.com/cloudflare/moq-rs/pull/274) *"serve Joining FETCH on draft-18"* (+5,936/−85) — so the registered `moq-rs-draft-18` relay can answer both standalone and joining FETCH at the interop target. All three landed in the **v0.7.30** train (Oct-14 18:54). (Joining FETCH was exactly the Section-10 gap that kept the Sep-2 conformance run at 43/59; this closes it on draft-18.)
- **draft-16 rewrite + PUBLISH support.** Manish (@itzmanish) closed his 155-day-old [PR #131](https://github.com/cloudflare/moq-rs/pull/131) and reopened it as [PR #170](https://github.com/cloudflare/moq-rs/pull/170) ("[Rewrite] Draft-16 migration"), the underlying draft-16 baseline (merged July 8). - **Namespace pub/sub and qlog alignment.** [PR #157](https://github.com/cloudflare/moq-rs/pull/157) (Suhas) added Publish/Subscribe Namespace support with a new relay `subscriber_registry`; [PR #163](https://github.com/cloudflare/moq-rs/pull/163) ([[mike-english]]) aligned mlog qlog output with draft-pardue-moq-qlog-moq-events-03.

On **Oct-6** this was extended on `main` into a full fetch stack — [PR #237](https://github.com/cloudflare/moq-rs/pull/237) *"joining fetch v1"* (+1,929/−91) adding the **Joining FETCH** that #236 had left unsupported, plus [PR #246](https://github.com/cloudflare/moq-rs/pull/246) *"public fetch APIs"* (+5,088/−252) and [PR #247](https://github.com/cloudflare/moq-rs/pull/247) *"moq-pub/sub fetch support"* (+7,721/−337), bringing **client-side fetch to `moq-pub`/`moq-sub` and the public library surface**.
