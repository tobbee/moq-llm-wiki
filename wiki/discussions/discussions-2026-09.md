## moq-transport: the "forward → paused" rename merges; two more editorial follow-on issues open

- **[PR #1940](https://github.com/moq-wg/moq-transport/pull/1940) *"Call the forwarding state paused"*** (afrind) **merged Sep-11 17:16 UTC** — the interim-23 forward-parameter-split rename is now on `main`. Recorded on [[moq-transport]] (disposition (1) updated: rename half **merged**).
- **[#1942](https://github.com/moq-wg/moq-transport/issues/1942) *"TRACK_NAMESPACE_PREFIX format is not defined for Control Message Parameters"*** ([[mathis-engelbart|Mathis Engelbart]], Sep-11 14:13 UTC) — §9.20 of draft-21 lists exactly four parameter value encodings (uint8, varint, Location, Length-prefixed), but the `TRACK_NAMESPACE_PREFIX` parameter (the field Sep-10's [#1930](https://github.com/moq-wg/moq-transport/pull/1930) renamed) uses the **Track Namespace encoding** from §8.7, which isn't one of them. Engelbart asks whether that encoding should be added to the list — a direct clean-up follow-on to the rename PR.
- **[#1943](https://github.com/moq-wg/moq-transport/issues/1943) *"Reserved Namespaces in NAMESPACE messages"*** ([[martin-duke|Martin Duke]], Sep-11 21:35 UTC) — §§2.4.2/6.5 say applications are rebuffed from reserved namespaces and such *requests* are ERRORed, but a **NAMESPACE / NAMESPACE_DONE** message is neither, and a reserved namespace can appear there when a `SUBSCRIBE_NAMESPACE` targets the empty namespace. Duke asks the correct behaviour (a `.` NAMESPACE presumably an error; `.session` presumably OK if not application-originated) and whether a reserved-namespace PUBLISH/PUBLISH_NAMESPACE should be answered `UNINTERESTED` rather than `DOES_NOT_EXIST`. These sit alongside Duke's open Sep-10 Mandatory-Track-Properties pair ([#1939](https://github.com/moq-wg/moq-transport/issues/1939)/[#1941](https://github.com/moq-wg/moq-transport/issues/1941)). The PR tells relays to carry the upstream value over, and to set the bit if they might add Properties of their own. ## URI resolution + TLS cert matching → a separate draft

The transport draft defines how a `moqt://` session behaves once connected but leaves two adjacent questions open: **how a client turns a `moqt` URI into an endpoint via DNS**, and **how a server's TLS certificate is validated against that URI**. [[cullen-jennings|Cullen Jennings]]'s Sep-5 list post frames the WG's converged answer — *"a separate spec is probably the best way to resolve this"* (from [issue #1839](https://github.com/moq-wg/moq-transport/issues/1839)) — with the practical rationale that a standalone document is easier for the DNS and certificate reviewers to sign off than text buried in the transport draft. Jennings and [[suhas-nandakumar|Suhas Nandakumar]] (both Cisco) put forward **[[moq-discovery|`draft-jennings-moq-discovery`]]** as that home and bumped it to **-02** the same afternoon. The draft was first tracked as a DNS/mDNS *discovery* draft (rev-00, Aug-14; see [[discussions-2026-08]]); this is the moment it graduates from a first-look individual I-D to the WG's candidate answer for a concrete transport gap. Transport-side, the split is being executed by OPEN [PR #1909](https://github.com/moq-wg/moq-transport/pull/1909) (*"Move URI resolution to a separate draft"*) and the earlier design-questions [PR #1901](https://github.com/moq-wg/moq-transport/pull/1901), and it sits alongside the URI-*query*-scope work already in draft-20 ([#1855](https://github.com/moq-wg/moq-transport/pull/1855)). See [[moq-transport]] and [[moq-discovery]].

## Prefix-based routing is the recurring relay-conformance gap

A single design theme ties the three relays together: **prefix-based announce routing**. [[steven-riedl|Steven Riedl]] gave the concrete reason from the client side — [[moq-dev|moq-net]] registers announce-interest with a **root/empty prefix**, so it *needs* a relay that routes announcements by prefix (a native client that subscribes to an *exact* namespace still works against exact-match relays, the same axis as the aiomoqt equality-vs-prefix bug). imquic had lost prefix routing, aiomoqt's relay did an equality check, and the Sep-2 [[moqtail]] and [[moq-rs]] relays had the same FETCH-side gap — so restoring prefix routing is what unblocks announce-subscribe across the roster. `moq-net`'s clean **6/6** (Sep-2, vs `relay18`) and **12/12** (Sep-3, vs Nokia) is the positive control that isolates the gap as relay-side, not client-side.

## Two moq-net / moq-rs wire bugs diagnosed for upstream

The sweep surfaced two concrete bugs in the [[moq-dev|moq-net]] / [[moq-rs]] Rust stack that Steven Riedl and Giovanni Marzot said they would take upstream to [[moq-dev]]:

- **Spurious `SUBSCRIBE_OK` extensions count.** Marzot's analysis: moq-rs's `KeyValuePairs::encode` (`moq-transport/src/coding/kvp.rs`) unconditionally writes a `len()` count before the KVP run, and `SubscribeOk` reuses that container for the trailing **Track Extensions** — so every `SUBSCRIBE_OK` moq-rs emits carries a spurious "Number of Extensions" varint (a captured `00`). Draft-16 Figure 12 defines Track Extensions as a **bare KVP sequence running to the message Length, with no count**. moq-rs's decoder is symmetric so it interops with itself; moxygen writes to-end per spec, so the two disagree on the wire. (For *parameters* the container's count happens to coincide with the message's explicit "Number of Parameters" field, so only the extensions position is wrong.)
- **ALPN-vs-SETUP version selection.** Riedl traced an `aiomoqt → stitcher-moq` failure (SETUP completes and reports a compatible version, then every subsequent case times out) to moq-net's `NEGOTIATED = [Lite02, Lite01, Draft14]`: for drafts 15–19 moq-net picks the wire version from the **ALPN** (`moqt-15`…`moqt-19`), while the SETUP version list only governs draft-14 and moq-lite. If a peer's SETUP-probe self-selects a draft that doesn't match the connection's ALPN, both ends look compatible at SETUP but then frame differently and the first post-SETUP control message goes nowhere. Riedl also noted moq-net's `ietf/publisher.rs` passes a **literal `404`** to `reject_subscribe` with no named `SUBSCRIBE_ERROR` code to map from — another item for moq-dev.

- **State transitions**: a nonexistent→existent object-state transition is a **"malformed track" error, not a connection-terminating protocol error**.
- **PR #1770 (default/updatable priority)** was **closed pending fresh mailing-list feedback**; **Top Tracks ([#1830](https://github.com/moq-wg/moq-transport/pull/1830))** will lean on the newly-merged **`PUBLISH_NOTIFY`** mechanism.
