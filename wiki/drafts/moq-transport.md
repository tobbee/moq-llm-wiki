# Abstract

MOQT is a publish/subscribe protocol that runs over QUIC and WebTransport. It leverages transport capabilities including streams, datagrams, priorities, and partial reliability. MOQT enables content delivery both directly between endpoints and through intermediate [[relays]], achieving scalable low-latency distribution. **Despite its name referencing media, the specification emphasizes that MOQT remains content-agnostic and applicable across various use cases** (abstract reframing in draft-18 — see [[discussions-2026-05]] for Will Law's parallel May 12 recharter proposal).

# Key Concepts

- **[[publish-subscribe]]**: Core messaging pattern - PUBLISH, SUBSCRIBE, FETCH, REQUEST_OK/REQUEST_ERROR, PUBLISH_DONE
- **[[subgroups-and-objects]]**: Data hierarchy: Track > Group > Subgroup > Object
- **[[relays]]**: First-class relay support for CDN-style distribution
- **[[track-properties]]**: Metadata attached to tracks and objects via Key-Value Pairs
- **[[joining-fetch|fill fetch]]**: Fetch-formatted delivery of past Groups when joining a live Track, requested via the `FILL_PARAMETERS` subscription parameter. **Replaced Joining FETCH in draft-20** ([#1673](https://github.com/moq-wg/moq-transport/pull/1673)) — the Joining variant of FETCH and the "standalone" moniker no longer exist.
- **[[qmux]]**: TCP fallback via QUIC multiplexing over TLS+TCP
- **URI Scheme**: `moqt://` URI scheme with fragment identifier support (PR #1571)

## draft-20 (published 2026-08-31)

Submitted to the datatracker Aug-31 at 20:11 UTC; **158 pages**. Itemised below from the draft's own **Appendix A.1** (*Since draft-ietf-moq-transport-19*) — raw text in `sources/ietf-drafts/draft-ietf-moq-transport-20.txt`.

**This is not a purely-editorial revision.** The [[interim-meetings|interim-2026-moq-21]] minutes forecast draft-20 as *"an editorial cut just before the editorial meeting"* (draft-20 → **draft-21 = the editorial meeting's output** → **draft-22 = the next official interop target**), and the ~11 PRs that merged on cut day were indeed cleanup. But the revision carries the **entire July 6 → Aug 31 window**, including several substantial wire changes — above all the removal of Joining FETCH. Implementations moving 19 → 20 have real work to do.

### Session and control plane
- **Joining FETCH replaced by fill fetch streams** ([#1673](https://github.com/moq-wg/moq-transport/pull/1673)) — the **Joining variant of FETCH is removed**, along with the "standalone" moniker. A fill is now requested by the new **`FILL_PARAMETERS`** parameter on a subscription, which itself carries a sequence of Parameters ([#1868](https://github.com/moq-wg/moq-transport/pull/1868)). See [[joining-fetch]].
- **Location Filter restructured** to match the other filter parameters, and the **FETCH range now travels in `LOCATION_FILTER`** instead of message fields ([#1809](https://github.com/moq-wg/moq-transport/pull/1809), [[mo-zanaty|Mo Zanaty]]).
- **`PUBLISH_STATE_NOTIFY` added** ([#1820](https://github.com/moq-wg/moq-transport/pull/1820), [[alan-frindell|afrind]]) — the strictly-informative subscription-state message.
- **`INCLUDE_PROPERTIES` parameter added** ([#1813](https://github.com/moq-wg/moq-transport/pull/1813), [#1847](https://github.com/moq-wg/moq-transport/pull/1847)).
- **`PUBLISH` can carry Subscription Parameters**, and AUTHORIZATION TOKEN is never copied from `SUBSCRIBE_TRACKS` ([#1834](https://github.com/moq-wg/moq-transport/pull/1834), [[ian-swett|ianswett]], closes [#1803](https://github.com/moq-wg/moq-transport/issues/1803)).
- Subscription parameters appear in `REQUEST_UPDATE`, not `PUBLISH_OK` ([#1790](https://github.com/moq-wg/moq-transport/pull/1790)); `FORWARD` allowed on a `REQUEST_UPDATE` for `SUBSCRIBE_TRACKS` ([#1812](https://github.com/moq-wg/moq-transport/pull/1812)).
- `SUBSCRIBE_TRACKS` Parameters are the publisher's initial Subscription parameters, explicitly communicated in the resulting `PUBLISH` ([#1815](https://github.com/moq-wg/moq-transport/pull/1815), [#1869](https://github.com/moq-wg/moq-transport/pull/1869)).
- **`PUBLISH_DONE`**: status code `SUBSCRIPTION_ENDED` removed — a subscription does *not* end because Largest Object passes the end of the Location Filter ([#1833](https://github.com/moq-wg/moq-transport/pull/1833)); maximum Stream Count raised to 2^64 − 1 ([#1831](https://github.com/moq-wg/moq-transport/pull/1831)).
- **Dead wire elements removed**: the `VERSION_NEGOTIATION_FAILED` session error ([#1867](https://github.com/moq-wg/moq-transport/pull/1867), vasilvv), the leftover `UNSUBSCRIBE` ([#1864](https://github.com/moq-wg/moq-transport/pull/1864), vasilvv), and the requirement for a publisher to retain Largest Location ([#1872](https://github.com/moq-wg/moq-transport/pull/1872), vasilvv).
- **Relays**: a relay MUST send an upstream FETCH to at least one publisher ([#1804](https://github.com/moq-wg/moq-transport/pull/1804)); the draft now discusses the tradeoffs of aggregating downstream filters onto a single upstream subscription ([#1735](https://github.com/moq-wg/moq-transport/pull/1735)).
- **`moqt://` URI**: host resolution defined ([#1817](https://github.com/moq-wg/moq-transport/pull/1817)); REDIRECT ambiguity with an empty Track Namespace *and* Track Name resolved ([#1824](https://github.com/moq-wg/moq-transport/pull/1824)); Retry Interval of 0 clarified ([#1785](https://github.com/moq-wg/moq-transport/pull/1785)); the query component excluded from the MOQT **scope** ([#1855](https://github.com/moq-wg/moq-transport/pull/1855)) — see the note at the end of this section.

### Data plane wire format and handling
- **`OBJECT_DATAGRAM` and `SUBGROUP_HEADER` types are now described as `Type Flags` bitfields** ([#1774](https://github.com/moq-wg/moq-transport/pull/1774)) — a parser-affecting change for every implementation. For `OBJECT_DATAGRAM`, **any set bit whose meaning is not specified is a `PROTOCOL_VIOLATION`**, and bit 4 (`0x10`) is reserved and MUST be zero. For `SUBGROUP_HEADER`, bit 4 MUST be **1**, `SUBGROUP_ID_MODE = 0b11` is reserved, and **any value ≥ 128** (i.e. needing more than a one-byte varint) is invalid.
- **`OBJECT_DELIVERY_TIMEOUT` now starts at the last header byte** rather than the first payload byte ([#1844](https://github.com/moq-wg/moq-transport/pull/1844), sharmafb, closes [#1841](https://github.com/moq-wg/moq-transport/issues/1841)).
- **End of Timed-Out Range** added for Objects abandoned when Fill Timeout expires ([#1822](https://github.com/moq-wg/moq-transport/pull/1822), afrind).
- Scheduling defined between fill-delivered and subscription-delivered Objects ([#1673](https://github.com/moq-wg/moq-transport/pull/1673)).
- **Beware re-using a Track Alias** for concurrent subscriptions ([#1856](https://github.com/moq-wg/moq-transport/pull/1856), ianswett, +16/−0, fixes [#1795](https://github.com/moq-wg/moq-transport/issues/1795)) — afrind asked whether re-use for the *same* track should also require the previous subscription to be done; Swett revised twice on Aug-21, concluding *"I don't think a subscriber can enforce that MUST"*, so the text advises receivers to treat stray objects as an unknown Track Alias instead.

### Security considerations
- **Preventing Impersonation** section added ([#1737](https://github.com/moq-wg/moq-transport/pull/1737), [#1789](https://github.com/moq-wg/moq-transport/pull/1789)).
- Mutual-TLS and authorization guidance expanded ([#1786](https://github.com/moq-wg/moq-transport/pull/1786)); `moqt` URI-scheme security considerations added ([#1772](https://github.com/moq-wg/moq-transport/pull/1772)).
- Security consideration for **logging untrusted string fields** ([#1823](https://github.com/moq-wg/moq-transport/pull/1823), afrind).
- **End-to-end object encryption recommended** for confidentiality from relays ([#1755](https://github.com/moq-wg/moq-transport/pull/1755), afrind, closes [#1711](https://github.com/moq-wg/moq-transport/issues/1711)) — points implementers at [[moq-secure-objects]].

### Notable editorial changes
- Range Filters section clarified for readability ([#1851](https://github.com/moq-wg/moq-transport/pull/1851), [[suhas-nandakumar|Suhas]]).
- The recommended track-name encoding is noted as **not guaranteed filename-safe** ([#1863](https://github.com/moq-wg/moq-transport/pull/1863)).
- LOC and Secure Objects entries fixed in the provisional Property registry ([#1807](https://github.com/moq-wg/moq-transport/pull/1807), [#1818](https://github.com/moq-wg/moq-transport/pull/1818), [#1848](https://github.com/moq-wg/moq-transport/pull/1848)).
- Typo / word-choice / punctuation pass ([#1862](https://github.com/moq-wg/moq-transport/pull/1862), afrind, +59/−59), plus the release-notes PR ([#1873](https://github.com/moq-wg/moq-transport/pull/1873), afrind).

**Left OPEN at the cut** and carried into the draft-21 restructuring: the two structural diagrams (Groups/Subgroups/Objects [#1866](https://github.com/moq-wg/moq-transport/pull/1866); MOQT scope [#1865](https://github.com/moq-wg/moq-transport/pull/1865), vasilvv) and the §11 datagram/object-header editorial refactor ([#1874](https://github.com/moq-wg/moq-transport/pull/1874), suhasHere).

**Note on [#1855](https://github.com/moq-wg/moq-transport/pull/1855) and the word "scope"**: this excludes the URI query component from the **MOQT scope**, which is the draft's *cache-key* term — *"two connection URIs that differ only in their query components identify the same scope."* The query component is **still part of the URI grammar** (`moqt-URI = "moqt" "://" authority path-abempty [ "?" query ]`) and is explicitly visible to the relay that terminates the client's connection. It is not "outside MoQT's purview".

## draft-18 (published 2026-05-12)

Key wire/spec changes from draft-17 (full list in **Appendix A.3** of the -20 text):
- **Remove Required Request ID** (PR #1615, materialises the Apr 27 interim consensus) — Required Request IDs are removed; Request IDs remain for individual requests — at the time, Joining FETCH and GOAWAY. **Both of those uses are since gone**: draft-19 removed the Request ID from GOAWAY ([#1623](https://github.com/moq-wg/moq-transport/pull/1623)) and draft-20 removed Joining FETCH ([#1673](https://github.com/moq-wg/moq-transport/pull/1673)).
- **Add FIRST_OBJECT bit to SUBGROUP_HEADER type** (PR #1618) — bit 6 (0x40) signals the subgroup contains the first object published by the original publisher; type byte expands `0b00X1XXXX` → `0b0XX1XXXX` (still 1-byte varint).
- **Forbid relays from lying about LARGEST_OBJECT** (PR #1621).
- **Split DELIVERY_TIMEOUT into two timeouts** (PR #1605) — `OBJECT_DELIVERY_TIMEOUT` (a more precise replacement for `DELIVERY_TIMEOUT`) plus a new `SUBGROUP_DELIVERY_TIMEOUT` (covers subgroups fully queued but not fully delivered). Closes the "DELIVERY_TIMEOUT is unimplementable" issue.
- **Improve Startup Latency and 0-RTT** (PR #1544) — new sections on reducing startup latency / 0-RTT flow with WebTransport.
- **Per-request GOAWAY** (PR #1617) — GOAWAY on request streams migrates individual requests; a zero-length URI causes the endpoint to re-issue the request on the specified URI session.
- **Improve Security Considerations** (PR #1625) — rebases and extends [[magnus-westerlund]]'s long-parked PR #1455.
- **Clarify definition of scope** (PR #1629).
- **Unified `moqt://` URI scheme** for both QUIC and WebTransport (PR [#1486](https://github.com/moq-wg/moq-transport/pull/1486)), with fragment-identifier support (PR [#1571](https://github.com/moq-wg/moq-transport/pull/1571)).
- **`SUBSCRIBE_NAMESPACE` split into `SUBSCRIBE_NAMESPACE` + `SUBSCRIBE_TRACKS`** (PR [#1542](https://github.com/moq-wg/moq-transport/pull/1542)) — the origin of the `SUBSCRIBE_TRACKS` message that later revisions keep reshaping (it appears 46 times in the -18 text and not at all in -17).
- **`REDIRECT` added** for request errors and established subscriptions (PR [#1534](https://github.com/moq-wg/moq-transport/pull/1534)).
- **`PUBLISH_OK` demoted** — the message type is removed and becomes a `REQUEST_OK` alias (PR [#1611](https://github.com/moq-wg/moq-transport/pull/1611)); textual aliases for `REQUEST_OK` defined per request type (PR [#1610](https://github.com/moq-wg/moq-transport/pull/1610)).
- **`FILL_TIMEOUT` parameter** (PR [#1490](https://github.com/moq-wg/moq-transport/pull/1490)) and **Track Properties on `REQUEST_OK`** (PR [#1576](https://github.com/moq-wg/moq-transport/pull/1576)); mandatory-to-understand track extensions (PR [#1509](https://github.com/moq-wg/moq-transport/pull/1509)).
- **Session-Level Tracks reserved namespace** (PR [#1562](https://github.com/moq-wg/moq-transport/pull/1562)); own tracks excluded from `SUBSCRIBE_NAMESPACE` (PR [#1596](https://github.com/moq-wg/moq-transport/pull/1596)).
- **Data-plane encoding**: Object ID and Group ID **delta-encoded in FETCH responses** (PR [#1586](https://github.com/moq-wg/moq-transport/pull/1586)), 7-byte varints and non-minimal encodings allowed (PR [#1595](https://github.com/moq-wg/moq-transport/pull/1595)), **padding streams and datagrams** (PR [#1475](https://github.com/moq-wg/moq-transport/pull/1475)), and the session closes when delta encoding wraps (PR [#1560](https://github.com/moq-wg/moq-transport/pull/1560)).
- Stream reset codes generalised to all request streams and aligned with `PUBLISH_DONE` (PR [#1606](https://github.com/moq-wg/moq-transport/pull/1606)); the session is no longer closed for unknown errors (PR [#1561](https://github.com/moq-wg/moq-transport/pull/1561)).
- Abstract and introduction rewritten (PR [#1556](https://github.com/moq-wg/moq-transport/pull/1556)), reframing MOQT as content-agnostic despite the "media" name.

# Open design questions

Substantive topics still being worked as this page is written:

- **Fill-fetch vs Joining FETCH (RESOLVED in draft-20)**: [PR #1673](https://github.com/moq-wg/moq-transport/pull/1673) (revising Subscription-Fill #1642) **merged into the draft-20 cut** — Joining FETCH and the "standalone" moniker are gone, replaced by `FILL_PARAMETERS` on a subscription plus fill fetch streams. [[cullen-jennings|Cullen Jennings]] had argued for keeping Joining FETCH pending operational experience and flagged error-delivery, duplicate-object and nested-`FILL_PARAMETERS` concerns; those **implementation concerns are now live questions against shipped text** rather than objections to a proposal. See [[joining-fetch]].
- **SSTS (Sender-Side Track Switching)**: the "Algorithm Zero + IANA registry" extension design (PR #1638), meant to be validated by more than one algorithm before draft-19. **At IETF 126 (July 20) the chairs called consensus to move SSTS into a *separate draft*, out of core transport** (contested by Cullen Jennings; AD affirmed the chairs) — so it is now slated to leave the transport document. See [[switch-abr]].
- **Range filters**: re-adding location-based subscription filters ([[mo-zanaty|Mo Zanaty]]'s PR #1765). **Slated to move into a separate draft** per the contested IETF-126 consensus call — the least-wanted part of the draft-18→19 delta (Luke Curley won't implement them; imquic ignores the property filters). In the interim, Mo Zanaty's **Location-Filter redesign to match the other filters' shape merged Aug-13** ([#1809](https://github.com/moq-wg/moq-transport/pull/1809), toward draft-20), while Suhas's [#1825](https://github.com/moq-wg/moq-transport/pull/1825) (July 22) — replacing the FORWARD parameter with Range-Filter-based pausing — stays OPEN.
- **Top Tracks Filter × SSTS/ABR interaction**: how the Top-Tracks-Filter ([PR #1830](https://github.com/moq-wg/moq-transport/pull/1830)) actually combines with SSTS (or any ABR algorithm) is unresolved. [[ian-swett|Ian Swett]]'s July-27 list thread *"Top Tracks and SSTS (or ABR in general)"* ([permalink](https://mailarchive.ietf.org/arch/msg/moq/2unKZrGYwvhNzPkqioijyv1DTpQ/)) argues ABR is essential for the video-conferencing use case and asks four concrete mechanism questions the current design doesn't answer: how to send the initial `SUBSCRIBE_TRACKS` (a Track-Property-Filter for the ideal resolution combined with Top Tracks?), how the focal viewport gets higher priority when deciding which feed to downswitch, how a client-pinned non-default feed is prioritized, and whether any demo (even simulated) shows the two working together. He notes Google Meet's production solution is *"sufficiently complex I can't summarize it"* and doubts MoQ will match it soon. Two implementers replied July 28 with a converging "discovery then selection" model: **[[yu-you|Yu You]] (Nokia)** framed it as a two-step pipeline — the Top-N filter answers *"what"* (evaluate a namespace's tracks by property value, promote the N highest, publisher subscribes upstream to all N) and SSTS answers *"how"* (apply the switching algorithm, e.g. a bandwidth threshold, to forward exactly one; the relay holds upstream to all N alternatives but sets downstream forwarding to 0 for the unselected, giving *"Top-1 delivery"* without overdelivery/congestion, and a demoted track leaves the switching set). **[[will-law|Will Law]] (Akamai)** cast Top Tracks as a discovery mechanism like `SUBSCRIBE_NAMESPACE` (clients assign the resulting tracks to switching sets via a `SWITCHING_SET_ASSIGNMENT` parameter on `PUBLISH_OK`), argued SSTS entry will lean on `SUBSCRIBE_NAMESPACE` + plain `SUBSCRIBE` more than dynamic Top-Tracks selection, and floated **unifying the two as one filter framework** — rename Top Tracks to `TRACK-FILTERS`, make SSTS parameters (rank, weight, throughput threshold) reserved track properties, and add a flag to "apply SSTS to the filtered tracks." Still open; Swett's demo-existence question (does *any* Top-Tracks + SSTS demo exist?) is unanswered.
- **Subgroup-start signalling**: draft-18 shipped the FIRST_OBJECT bit (PR #1618), but the list debated alternatives (Subgroup ID == first Object ID; Luke Curley's per-subgroup counter for cache-gap detection).
- **Compression layering**: whether compression belongs at the transport, [[moq-msf|MSF]]/streaming-format, or Full-Track-Name layer, and hop-by-hop vs end-to-end semantics. See [[moq-dev]].
- **7-byte varint / non-minimal encodings**: allowed since draft-17 (PR #1595), but flagged as a footgun in the draft-19 read-through.
- **PUBLISH_STATE_NOTIFY** (formerly proposed as SUBSCRIPTION_STATE_UPDATE / PUBLISH_NOTIFY): [[alan-frindell|afrind]]'s new *strictly-informative* control message to notify subscription state — **[PR #1820](https://github.com/moq-wg/moq-transport/pull/1820) MERGED 2026-08-13** into the editor's copy (toward draft-20). Still open is the related question [issue #1821](https://github.com/moq-wg/moq-transport/issues/1821) (Otto Hermann): *what a subscriber is entitled to observe after an Object becomes unavailable* — both touch draft-19's clarified subscription-state destruction timing.
- **FETCH and REQUEST_ERROR encoding**: [[mathis-engelbart|Mathis Engelbart]]'s [issue #1837](https://github.com/moq-wg/moq-transport/issues/1837) (July 31) raises an encoding question on FETCH and REQUEST_ERROR. **Reactivated Aug-20/21**: [[alan-frindell|afrind]] posted a *"reminder to chime in if you want this change,"* and **[[martin-duke|Martin Duke]] staked out a third position (Aug-21)** — *"I would prefer three message types to the status quo, but moving joining fetch to a SUBSCRIBE parameter is superior to both."* That ties this encoding question directly to the [[joining-fetch|Joining-FETCH / fill-fetch]] redesign in [#1673](https://github.com/moq-wg/moq-transport/pull/1673) — **which has since merged in draft-20**, so Duke's preferred "joining fetch as a SUBSCRIBE parameter" is now essentially what the draft does. Still no PR on the encoding question itself.
- **Track Alias re-use** (RESOLVED in draft-20): [[ian-swett|Ian Swett]]'s [PR #1856](https://github.com/moq-wg/moq-transport/pull/1856) (opened Aug-20, +16/−0, fixes [#1795](https://github.com/moq-wg/moq-transport/issues/1795)) adds guidance on re-using a Track Alias **for a different Track**. afrind asked whether re-use for the *same* track should also require the previous subscription to be done; Swett revised twice on Aug-21, concluding *"I don't think a subscriber can enforce that MUST"* and instead advising receivers to treat stray objects as an unknown Track Alias. **Merged Aug-31 in the draft-20 cleanup cut.** **Follow-on (Sep-1):** [[ian-swett|Swett]]'s [issue #1875](https://github.com/moq-wg/moq-transport/issues/1875) *"Forcing SUBSCRIBE to always use Track Alias is becoming complex"* reopens the tension — the always-Track-Alias model is accreting edge cases — with OPEN [PR #1876](https://github.com/moq-wg/moq-transport/pull/1876) proposing Track Alias be **returned as a SUBSCRIBE_OK parameter** instead of mandated on every SUBSCRIBE. Unresolved as the draft-21 restructuring settles.

- **Metadata scope between Track and Object**: [michalhosna](https://github.com/michalhosna)'s [issue #1857](https://github.com/moq-wg/moq-transport/issues/1857) (opened during the Aug-24 interim) observes that MoQT has Track-scoped metadata (Track properties) and Object-scoped metadata (object parameters) but **nothing scoped to a Subgroup or Group** — and that emulating a group/subgroup scope via object parameters (e.g. `SUBGROUP_DELIVERY_TIMEOUT`/`OBJECT_DELIVERY_TIMEOUT`, `PRIOR_GROUP_ID_GAP`) is awkward and error-prone. New, no PR yet.
- **Updatable PUBLISHER_PRIORITY (PR #1770)**: [PR #1770](https://github.com/moq-wg/moq-transport/pull/1770) would let a publisher change its priority mid-stream. Both the [[interim-meetings|Aug-10 interim]] and the Aug-24 interim leaned toward **rejecting** it — few in the WG (zero in the Aug-10 room) found the savings worth the machinery. The list debate then reopened it: [[cullen-jennings|Cullen Jennings]] (Aug-24) split the PR into *allowing priority changes* — which he supports (e.g. a conferencing bridge raising the active-speaker video track above the other feeds) — and *eliminating race conditions*, which he agrees need not be solved because relay priorities are imprecise anyway. **[[alan-frindell|afrind]] replied Aug-26** ([permalink](https://mailarchive.ietf.org/arch/msg/moq/Z3lqj-lseqzChRlisQ10pyehbjk/)) clarifying the savings are **at most one byte** per datagram/subgroup (not the "2-3 bytes" Cullen cited) and proposing to gate the priority-change feature behind a **SETUP opt-in** or move it to an **extension document** — while insisting the PR's two base-draft changes (moving Default Publisher Priority back from a property to a **parameter**, and relaxing the malformed-track rules around priority) **must land in the base draft regardless**. **The thread continued Aug-27**, shifting from *whether* to *how*: [[suhas-nandakumar|Suhas Nandakumar]] ([permalink](https://mailarchive.ietf.org/arch/msg/moq/lxEBTq4_BjJQZJldXIjhnXZS2aM/), 03:45 UTC) backed both allowing priority changes and relays using them for compression, agreed the interim sentiment was not to chase a perfect race-avoidance solution, and floated a **NOTIFY** to inform subscribers of a change; [[alan-frindell|afrind]] ([permalink](https://mailarchive.ietf.org/arch/msg/moq/zI1BXiQA-XmqJUkGAAwh0mXjsAU/), 15:06 UTC) argued **REQUEST_UPDATE beats PUBLISH_STATE_NOTIFY** here — the REQUEST_OK tells the publisher exactly when it is safe to drop explicit per-object priority and resume compressing — and that including **LARGEST_OBJECT** when changing `DEFAULT_PUBLISHER_PRIORITY` lets a receiver reconstruct priority cheaply; # ALPN Negotiation

MOQT negotiates the draft revision **entirely via the QUIC ALPN** ([RFC7301]) and WebTransport's `WT-Available-Protocols`. Draft ALPNs are formed by appending the draft number to `moqt-`; the final RFC will use the bare `moqt` token.

**From draft-15 onward there is no numeric wire version at all** — draft-20 §3.1 makes ALPN the sole version-negotiation mechanism, and drafts 16–20 contain no `Supported Versions` / `Selected Version` SETUP fields. The `0xff0000NN` version codes belong to **draft-14 and earlier**, which used a single `moq-00` ALPN followed by numeric version negotiation inside the SETUP messages (draft-14 §9.3 defined draft versions as `0xff000000` + draft number, so draft-14 = `0xff00000E`). Implementation pages that quote a `0xff0000NN` constant for a draft ≥ 15 are quoting an implementation's internal enum, not a spec-defined wire value.

The QUIC-multiplexed ([[qmux]]) transport prefixes the same token as `qmux-00.moqt-NN`; that composition is defined in the qmux draft, not in moq-transport.

- `moqt-20` — draft-20, the current published revision
- `moqt-19` — draft-19
- `moqt-18` — draft-18; the Vienna interop target and the current automated interop-runner target
- `moqt-17` — draft-17
- `moqt-16` — draft-16
- `moq-00` — draft-14 and earlier (legacy, numeric SETUP version negotiation); the bare `qmux-00` token (no suffix) likewise implies draft-14
